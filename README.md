# make-knowledge-cards

把文章或本地 Markdown / TXT 文件转成结构化知识卡片，用于主动复习和间隔回顾。

---

## 1. 这个项目解决什么问题

读完就忘，是这个 Skill 要解决的唯一问题。

具体痛点是三个：

- **划重点等于没划。** 高亮、收藏、复制金句，都不会让知识进入长期记忆，因为缺少"主动回想"这一步。
- **手工整理复习卡片太贵。** 一张合格的卡片要提炼核心、写清解释、配例子或自测题，一篇长文做下来要一小时，多数人因此放弃。
- **用 AI 批量生成卡片容易失真。** 通用模型为了凑够数量，会重复表达同一个点、拆分同一个概念、甚至补上原文没有的"常识"。这种卡片复习时是有害的——你在记住错误的东西。

这个 Skill 的做法是：把"提炼卡片"这件事的标准流程写死在一个可复用的定义文件里，让模型每次都按同一套过滤器工作——**只留真正重要的、一张只讲一个点、不重复、不编造、不够就不凑数**。

它不是摘要工具。摘要是"看完知道讲了什么"，卡片是"能用来考自己"。

## 2. 主要功能

### 支持的输入

两种，任选其一：

- **直接粘贴的文章文本**（对话里粘贴即可）
- **本地 `.md` / `.txt` 文件的绝对路径**

### 卡片格式

每张卡片固定四部分：

| 字段 | 作用 |
|------|------|
| **标题** | 一句话点出本卡的知识点，不超过 18 个汉字或 12 个英文单词 |
| **核心知识** | 一句话陈述关键事实、定义或结论，必须是陈述句 |
| **简明解释** | 2–4 句讲清楚，包含必要的限定条件、边界或反例 |
| **例子 / 自测** | 二选一：原文的具体例子，或一道带可验证答案的自测题 |

### 保证质量的三道过滤器

按顺序应用，全部通过才会成为一张卡片：

1. **重要性** — 丢掉开场白、作者个人看法、营销话术、装饰性内容
2. **原子性** — 一张卡只讲一个点；一段里有两件事就拆开，两段讲同一件事就合并
3. **忠实原文** — 每一句都能在原文找到依据；原文没给的补充，宁可删掉也不编

### 卡片数量由内容决定，不由篇幅决定

**5–8 张是上限，不是目标。**

- 原文只有 4 个真正独立的点 → 就输出 4 张
- 原文是纯日记、纯观点、纯流水账，没有任何可提炼的知识 → 输出 **0 张**，并说明原因、建议补充什么背景

如果明确要求"做 8 张"但原文只支撑 5 张，Skill 会先告知，再问是放宽数量还是补充材料。

### 其他

- 自动去重：定稿前扫描全部卡片，合并或删除重复
- 语言跟随原文；用中文提问就用中文回答
- 输出纯 Markdown，可直接粘进 Obsidian、Notion、Logseq 等工具

### 当前不做什么

这些都是明确的边界，遇到会直接拒绝并引导回支持范围：

- 不抓取网页 / URL
- 不读取 PDF、DOCX、EPUB 等二进制文件
- 不导出 Anki `.apkg`、CSV、JSON 等外部格式
- 不提供图形界面

> 想处理的材料不在支持列表里时，先把内容转成 `.md` / `.txt` 或粘贴文本即可。

## 3. 安装方法

仓库里的 `skills/make-knowledge-cards/` 是源码位置。**要真正启用，需要把它放到 WorkBuddy 会加载的目录下**：

### 方式一：安装为项目级 Skill（只在本仓库生效）

```bash
# 在项目根目录执行
mkdir -p .workbuddy/skills
cp -r skills/make-knowledge-cards .workbuddy/skills/
```

安装后路径应为 `<项目根目录>/.workbuddy/skills/make-knowledge-cards/`，对该仓库的所有协作者生效。

### 方式二：安装为用户级 Skill（所有项目生效）

```bash
mkdir -p ~/.workbuddy/skills
cp -r skills/make-knowledge-cards ~/.workbuddy/skills/
```

Windows 上用户级目录通常是 `%USERPROFILE%\.workbuddy\skills\`。

### 方式三：在 OpenAI / ChatGPT 平台使用

`skills/make-knowledge-cards/agents/openai.yaml` 是一个独立的 Agent 配置文件，可直接导入 OpenAI 的 Agent 平台或用于创建 Custom GPT。它复用了 `SKILL.md` 的完整工作流，精简为单文件可加载的指令，并内置了 4 个对话引导词。

### 验证安装

```bash
python <skill-creator>/scripts/quick_validate.py skills/make-knowledge-cards
# 输出 "Skill is valid!" 即通过
```

## 4. 使用方法

### 触发方式

安装后，在对话中直接说出意图即可。以下说法都会触发：

```
把这段文章做成知识卡片
把这个 Markdown 文件做成复习卡片：<文件路径>/raft.md
这篇文章能提炼几张知识卡片？
帮我把这篇教程做成 5 张知识卡片
总结成卡片 / 提炼要点 / 做个闪卡
```

### 可选参数

可以在请求里附带，不写则自动推断：

| 参数 | 说明 |
|------|------|
| 卡片数量 | 5–8 之内；不指定时按原文独立概念数推断 |
| 难度 | 如"入门级""进阶"，影响解释的深度 |
| 语言 | 默认跟随原文；中文提问则中文输出 |

### 典型流程

1. 粘贴文章，或给出 `.md` / `.txt` 文件的绝对路径
2. Skill 通读全文，用三道过滤器筛出知识点
3. 输出：一行主题与数量说明 → 编号卡片 → 一行"本次舍弃了什么"的说明

第三行的舍弃说明是刻意设计的，方便你判断有没有漏掉关心的部分。

## 5. 输入输出示例

### 示例 A：常规技术文章

**输入**（粘贴的文本）：

> 缓存穿透是指查询一个一定不存在的数据，由于缓存不命中，每次都会去数据库查询，导致数据库压力过大。常见的解决方案有两种：缓存空对象和使用布隆过滤器。缓存空对象的优点是实现简单，缺点是会浪费内存；布隆过滤器的优点是空间效率高，缺点是存在误判。

**输出**：

> 以下从原文提炼出 3 张知识卡片（原文只展开到 3 个核心概念，未做更多延伸）。
>
> ## 1. 缓存穿透的定义
>
> **核心知识**：缓存穿透指查询一个一定不存在的数据，因缓存不命中导致每次请求都打到数据库。
>
> **简明解释**：普通的缓存未命中至少可能命中数据库中的真实数据，而缓存穿透的查询 key 在数据库中也不存在，因此无法通过回种缓存来缓解。
>
> **例子 / 自测**：
> - **自测**：一个不存在的用户 ID（如 -1）被高频访问时会发生什么？
> - **答案**：每次请求都直接落到数据库，绕过缓存，造成数据库压力上升。
>
> ## 2. 缓存空对象
>
> **核心知识**：缓存空对象是把数据库中不存在的 key 也写入缓存（值标记为空）。
>
> **简明解释**：实现简单，只需在查询逻辑里多写一次 SET。代价是会持续占用内存，因此需要为这类 key 设置较短的过期时间以避免长期堆积。
>
> **例子 / 自测**：
> - **例子**：查询 `user_id=-1` 未命中数据库后，缓存写入 `"user:-1" -> ""`，TTL=60s。
>
> ## 3. 布隆过滤器
>
> **核心知识**：布隆过滤器是一个空间效率很高的概率型数据结构，用于判断元素是否存在。
>
> **简明解释**：优势是占用内存远小于直接缓存空对象。代价是存在误判：可能把"不存在"判为"存在"，因此通常作为前置过滤层，命中后再去缓存或数据库查实。
>
> **例子 / 自测**：
> - **例子**：在请求入口先用布隆过滤器判断 key 是否可能存在；只有通过时才查缓存和数据库。

### 示例 B：信息不足时不凑数

**输入**（`test/articles/04-thin-daily.md`）：

> 今天下午开会时间又改了。主管说项目要加快进度，但预算还没批下来。我们组的人都觉得很累。我点了杯冰美式。晚上回家煮了面条，加了一个鸡蛋。

**输出**：

> 这篇原文是个人流水账记录，不含可提炼的独立知识点。原文中提到的开会改期、预算未批、组员疲惫、晚餐内容等都是个人事件，没有可独立成"知识点"的原理、概念或机制。
>
> 按"不能编造原文没有的信息"和"信息不足不强凑数量"两条原则，**本次输出 0 张知识卡片**。
>
> 建议：如果你希望从这篇日记里获得复习卡片，可以补充一些背景（如：项目为何超预算？你组疲惫的根源是什么？）然后再让我提炼。否则，这篇内容更适合作为日记保留。

### 四篇测试文章的真实输出

`test/articles/` 下提供了 4 个不同类型的测试样本，实测结果：

| 测试文件 | 类型 | 输出卡片数 |
|---------|------|-----------|
| `01-short-tcp-handshake.md` | 短篇技术文（单主题） | 5 |
| `02-medium-consensus.md` | 中等长度、多主题 | 7 |
| `03-long-deep-work.md` | 长文、多概念 | 8 |
| `04-thin-daily.md` | 日记（无可提炼知识） | 0 |

> **说明**：`SKILL.md` 的 Example 2 以"深度工作"为主题举例时给出 6 张，而上表中 `03-long-deep-work.md` 是 8 张。二者不矛盾——Example 2 假设的原文只有 4 个概念，而真实测试文件还多出"安排深度工作的四条原则"和"深度工作的本质"两个独立要点。这正是"卡片数量由独立概念数决定，而非由文章长度决定"这条规则的体现。
