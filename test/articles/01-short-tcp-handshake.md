# TCP 三次握手

TCP 建立连接时需要三次握手，目的是让双方都确认自己和对方的收发能力都正常。

第一次握手：客户端发送 SYN=1，初始序号 seq=x，进入 SYN_SENT 状态。
第二次握手：服务器收到 SYN 后，发送 SYN=1、ACK=1，确认号 ack=x+1，自己的序号 seq=y，进入 SYN_RCVD 状态。
第三次握手：客户端收到服务器的 SYN+ACK，发送 ACK=1，ack=y+1，进入 ESTABLISHED 状态；服务器收到后也进入 ESTABLISHED 状态。

为什么不能只用两次握手？如果只有两次，服务器无法确认客户端是否已经准备好接收数据。两次握手下，服务器发出 SYN+ACK 后就认为连接已建立，但这个 SYN+ACK 可能丢失，客户端会重发 SYN；或者旧的 SYN 报文段到达服务器，造成服务器单方面建立连接而客户端并不知情。三次握手通过让客户端再发一次 ACK，确保双方都进入了 ESTABLISHED。

SYN 洪泛攻击的原理是攻击者不断发送伪造源 IP 的 SYN 报文，服务器为每个 SYN 分配半连接资源并发送 SYN+ACK，但永远不会收到 ACK，最终耗尽连接资源。常见的防御方法包括 SYN Cookie 和缩短半连接超时时间。
